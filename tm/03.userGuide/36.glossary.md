---
title: Glossary
---

The Glossary is a list of terms you want translated the same way every time - product names, job titles, industry words - along with the terms you never want translated at all.

It is a single, global list for the site. Each term is written once in its source language, and then given a value for each language you translate into (or marked as "do not translate" for that language). Connectors that support the glossary read it when they translate, so the same phrase comes back the same way each time.

:::note Not every connector uses it
The glossary is only useful to a connector that reads it. The Glossary screen tells you which of your installed connectors support it - if none of them do, adding terms will not change your translations.
:::

## Turning the glossary on

The glossary is **off** by default, and the menu item is hidden until something switches it on. There are two ways in:

- a connector that supports the glossary is configured to use it, or
- you set `GlossaryEnabled` to `true` in the `Translation` section of `appsettings.json`:

```json
{
  "Translation": {
    "GlossaryEnabled": true
  }
}
```

Once it is on, **Glossary** appears in the Translations section, below the job lists.

:::note Who can see it
Seeing the Glossary needs the **View glossary** permission as well as access to the Translations section. Administrators are granted it automatically; other user groups have to be given it explicitly.
:::

## Adding terms

The Glossary screen works one language pair at a time. Pick the language your content is written in on the left, and the language you are translating into on the right - the table then shows every term along with its value for that target language.

**Add Term** opens a panel with:

- **Source Text** - the word or phrase as it appears in your content.
- **Notes** - a reminder for whoever edits the glossary next. Notes are never sent to the translation service.
- **Case sensitive** - off by default, so `Dashboard` and `dashboard` are treated as the same term. Turn it on when the casing matters and two spellings genuinely mean different things.
- a value row for every installed language, so you can fill in all of them at once rather than switching pairs.

Each value row has a **Do not translate** switch. Turning it on tells the connector to leave that term exactly as written for that language, and the value box is ignored - useful for brand and product names.

:::tip Do not translate is per language
A term can be translated in one language and left alone in another. Set it per row rather than for the whole term.
:::

## Finding things

- The **search** box filters on the source text.
- **Missing only** narrows the list to terms that have no value yet for the language you are translating into - the quickest way to see what is left to do after adding a language.
- The counts beside the filters show how many terms have a value for that language, how many are still missing, and how many are marked do-not-translate.

## Import and export

Editing terms one at a time is fine for a handful. For more, use **Import** and **Export** at the bottom of the screen. Both offer two formats.

### CSV - one language pair at a time

A simple three-column file: your source language, your target language, and a `doNotTranslate` column.

```csv
en-US,fr-FR,doNotTranslate
dashboard,tableau de bord,false
Brightbox,,true
```

This is the format to hand to a translator: export the pair, let them fill in the middle column, import it back. The file is written with a byte order mark so Excel opens it as UTF-8 and accented characters survive the trip.

### TBX - every language in one file

TBX (ISO 30042) is the interchange format most termbase tools understand. Exporting gives you every language you hold values for in a single file, which is the right choice for moving a glossary between sites or importing one from another tool.

### Importing replaces, it does not merge

**An import replaces everything stored for the languages the file covers.** A term that exists in the glossary but is missing from the file loses its value for that language.

That is deliberate - it means the file you import is exactly what you end up with, rather than leaving behind values nobody can see in the file they are working from. It does mean that if you export a pair, delete all but one row, and import it back, you will be left with one term.

If you only want to change a few terms, edit them on screen rather than importing a partial file.

Import tells you afterwards how many terms it created, how many it matched, and how many values it wrote, along with any warnings - for example rows whose source term does not exist when **Create missing terms** is switched off.

:::warning One language pair per CSV
A CSV import only ever touches the pair you select. Other languages are left exactly as they are - so importing French never disturbs your German values.
:::

### If the file is wrong

A file that cannot be read is rejected whole, and nothing in the glossary changes. A truncated TBX file, or a CSV whose header does not match the languages you picked, comes back as an error with the glossary untouched - there is no half-applied import to clean up.

## Clearing a language pair

**Clear** removes every value for the pair currently selected. The terms themselves stay, along with their values in other languages. Use it when you want to start a language again from scratch.
