---
title: Upgrading from Umbraco 13
---

Translation Manager's data upgrades with your site. Sets, jobs, job history, connector settings and your `appsettings.json` config all come across from v13 to v17 and then to v18. You don't export anything or set anything up again.

You do need to change which packages the site references, because the package names changed between v13 and v17.

## Before you start

### Licence

A Translation Manager project licence covers one Umbraco LTS version and the versions up to the next one. A v13 licence doesn't work on v17, so you need an upgrade. See [licences](https://docs.jumoo.co.uk/licences).

Subscription and agency licences work on every version while they are active, so there's nothing to buy.

### Finish your translation jobs

Approve or archive any jobs that are still open before you upgrade. Jobs created on v13 can still be approved after the upgrade, but a job that crosses an upgrade is one more thing to check afterwards.

### Get to the latest v13

Upgrade Umbraco and Translation Manager to the latest v13 releases first, and check the site works. Umbraco expects this too: its own v17 migrations log warnings when the site wasn't on the latest v13.

## 1. Update your packages

In v13 each connector was a `Jumoo.TranslationManager.Connector.*` package. From v17 they are `Jumoo.TranslationManager.*`, and several v13 packages are no longer separate.

| v13 package | v17 / v18 |
|---|---|
| `Jumoo.TranslationManager` | `Jumoo.TranslationManager` |
| `Jumoo.TranslationManager.Connector.Passthrough` | Included in `Jumoo.TranslationManager` |
| `Jumoo.TranslationManager.Connector.Xliff` | Included in `Jumoo.TranslationManager` |
| `Jumoo.TranslationManager.Connector.Google` | Included in `Jumoo.TranslationManager` |
| `Jumoo.TranslationManager.Connector.Microsoft` | Included in `Jumoo.TranslationManager` |
| `Jumoo.TranslationManager.Connector.DeepL` | Included in `Jumoo.TranslationManager` |
| `Jumoo.TranslationManager.OpenAi` | `Jumoo.TranslationManager.AI`, included in `Jumoo.TranslationManager` |
| `Jumoo.TranslationManager.Assets`, `.PropertyCopier`, `.BlockMerger` | Part of the main package, remove them |

So for most sites the change in the `.csproj` is:

```xml
<!-- remove -->
<PackageReference Include="Jumoo.TranslationManager.Connector.DeepL" Version="13.0.0" />

<!-- change -->
<PackageReference Include="Jumoo.TranslationManager" Version="17.*" />
```

Remove any `Connector.*` package you referenced directly. Connectors for other services (CrowdIn, LanguageWire, GlobalLink and so on) have their own v17 packages. Check each one is available for the version you're moving to before you upgrade.

The OpenAI connector stops at v13. On v17 use the AI connector, which includes OpenAI. Your OpenAI API key still works.

## 2. Upgrade Umbraco

Follow Umbraco's own upgrade guide for the rest of the site: the target framework, `Program.cs` and anything else in your own code. Translation Manager needs no extra code in `Program.cs`.

The v13 Translation Manager screens were AngularJS. They came from the package itself, so removing the v13 package removes them, and there are no files to clean up in `App_Plugins`. If you customised those screens, the customisations don't carry over to the new backoffice.

## 3. Start the site

With unattended upgrades on, Umbraco runs its migrations and then Translation Manager's. Translation Manager logs each step it runs, starting with `Starting 'TranslationManager'...` and ending with `Done`.

The upgrade:

- moves job and history records from user ids to user keys, as the new backoffice needs
- keeps your sets, jobs, history and connector settings as they were
- adds the tables for translation memory and the glossary
- gives the **Administrators** group the Translation Manager permissions

## 4. Check permissions

After the upgrade, only Administrators get every Translation Manager permission automatically. The **Translators** group gets *Send to translation*, and a group that has *Manage translations* also gets *Approve translations* and *Publish translations*. Give any other group what it needs in *Users -> Groups*:

- Send to translation
- Manage translations
- Approve translations
- Publish translations
- View glossary
- View translation memory

Each user also needs access to the **Translations** section. Users who were signed in during the upgrade should sign out and back in to pick up new permissions.

## Where things are now

- Jobs are in the **Translations** section, under Pending, Submitted, Received and Approved. The Glossary and Memory are there too.
- Sets and connector settings are in *Settings -> Translations -> Translation Manager*.

## Moving on to v18

From v17, upgrade to v18 the same way: change the Umbraco and Translation Manager package versions to 18.

:::warning
If the v17 site is on Translation Manager 17.7.0 or later, use the first Translation Manager release after 18.5.0. Version 18.5.0 doesn't recognise the migration state that later v17 releases leave, and stops with `The migration plan "TranslationManager" does not support migrating from state ...`.
:::
